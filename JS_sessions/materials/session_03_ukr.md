# Конспект з JavaScript: Функції, Налагодження, Помилки та Керування пам'яттю

Комплексний конспект для підготовки до лекцій, повторення матеріалу та технічних співбесід.

---

## 1. Функції в JavaScript: Базові механізми

### 1.1 Область видимості (Scope)

Область видимості визначає доступність змінних та функцій у різних частинах коду під час виконання. У JavaScript використовується **лексична область видимості** (lexical/static scoping): межі доступності визначаються розташуванням змінних і блоків безпосередньо у вихідному коді на етапі написання.

#### Рівні області видимості

1. **Глобальна область видимості (Global Scope):**
   * Змінні, оголошені поза будь-якою функцією або блоком коду.
   * Доступні з будь-якого місця програми.
   * У браузерному середовищі змінні, оголошені через `var` на верхньому рівні, стають властивостями об'єкта `window`, тоді як `let` і `const` до нього не додаються.

2. **Функціональна / локальна область видимості (Function Scope):**
   * Змінні, оголошені всередині функції, доступні лише всередині неї та її вкладених функцій.
   * Ключові слова `var`, `let` та `const` поважають межі функціональної області.

3. **Блокова область видимості (Block Scope, ES6+):**
   * Змінні, оголошені всередині блоку (`{ ... }`) за допомогою `let` або `const`, недоступні за його межами.
   * `var` **не підтримує** блокову область видимості: змінна «витікає» на рівень найближчої функції або глобального контексту.

```javascript
{
  var leakedVar = "доступна ззовні";
  let scopedLet = "ізольована всередині";
  const scopedConst = "також ізольована";
}

console.log(leakedVar);   // "доступна ззовні"
console.log(scopedLet);   // ReferenceError: scopedLet is not defined
```

4. **Ланцюжок областей видимості (Scope Chain):**
   * Коли інтерпретатор шукає змінну, він спочатку перевіряє поточну локальну область. Якщо її там немає — переходить до зовнішньої (батьківської) області, піднімаючись угору аж до глобальної. Якщо змінну знайти не вдалося, викидається `ReferenceError`.

### 1.2 Підняття (Hoisting)

**Hoisting** — це механізм JavaScript, за якого оголошення функцій, змінних або класів переміщуються у верхню частину своєї області видимості на фазі створення контексту виконання (до безпосереднього виконання коду).

#### Поведінка різних типів оголошень

| Оголошення | Піднімається (Hoisted)? | Початкове значення | Спроба звернення до оголошення |
| :--- | :--- | :--- | :--- |
| **`function` declaration** | Так | Тіло самої функції | Працює коректно, функцію можна викликати |
| **`var`** | Так | `undefined` | Повертає `undefined` |
| **`let`** | Так | *Неініціалізовано* (TDZ) | Викидає `ReferenceError` |
| **`const`** | Так | *Неініціалізовано* (TDZ) | Викидає `ReferenceError` |
| **Function Expression (`var`)** | Так (тільки змінна) | `undefined` | `TypeError: ... is not a function` при виклику |
| **Function Expression (`let`/`const`)** | Так (тільки змінна) | *Неініціалізовано* (TDZ) | Викидає `ReferenceError` |

#### Тимчасова мертва зона (Temporal Dead Zone, TDZ)

TDZ — це період між моментом входу в область видимості та фактичним рядком коду, де змінна `let` або `const` оголошується та ініціалізується. Будь-яке звернення до змінної у межах цієї зони спричиняє помилку `ReferenceError`.

```javascript
// Function Declaration: піднімається повністю разом з реалізацією
greet(); // "Привіт!"
function greet() {
  console.log("Привіт!");
}

// var: оголошення піднімається, значення ініціалізується як undefined
console.log(a); // undefined
var a = 10;

// let/const: потрапляють у Temporal Dead Zone (TDZ)
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 20;

// Function Expression з var: піднімається лише змінна зі значенням undefined
sayHi(); // TypeError: sayHi is not a function
var sayHi = function() {
  console.log("Hi");
};
```

### 1.3 Замикання (Closures)

**Замикання** — це комбінація функції та її лексичного оточення (змінних зовнішньої області), у якому ця функція була створена. Замикання надає внутрішній функції доступ до змінних зовнішньої функції навіть після того, як зовнішня функція завершила своє виконання.

#### Як це працює

Зазвичай локальні змінні функції видаляються з пам'яті після її завершення. Однак, якщо внутрішня функція продовжує зберігати посилання на ці змінні, вони залишаються активними у купі (Heap).

```javascript
function createCounter(initialValue = 0) {
  let count = initialValue; // Приватна змінна, інкапсульована замиканням

  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getCount() {
      return count;
    }
  };
}

const counter = createCounter(5);
console.log(counter.increment()); // 6
console.log(counter.increment()); // 7
console.log(counter.decrement()); // 6
console.log(counter.count);       // undefined (прямого доступу до count немає)
```

#### Типові сценарії використання

* **Інкапсуляція даних та імітація приватного стану:** приховування внутрішніх змінних від прямого доступу ззовні (до появи синтаксису приватних полів `#field` у класах).
* **Фабрики функцій (Function Factories):** створення спеціалізованих конфігурованих функцій (наприклад, генераторів префіксів, логерів).
* **Карування (Currying) та часткове застосування:** перетворення функцій багатьох аргументів на послідовність функцій одного аргументу.
* **Обробники подій та асинхронні виклики:** збереження контексту виконання між асинхронними подіями.

---

### 1.4 IIFE (Immediately Invoked Function Expression)

**IIFE** — це функціональний вираз, який виконується негайно після свого створення.

#### Синтаксис і приклади

```javascript
// Класичний анонімний вираз IIFE
(function() {
  const privateToken = "secret_123";
  console.log("IIFE виконано негайно!");
})();

// Варіант зі стрілочною функцією
(() => {
  console.log("Стрілочний IIFE відпрацював!");
})();

// Передача параметрів та повернення значення
const appConfig = (function(env) {
  const apiUrl = env === "production" ? "https://api.site.ua" : "http://localhost:3000";
  return {
    apiUrl,
    isProd: env === "production"
  };
})("production");

console.log(appConfig.apiUrl); // "https://api.site.ua"
```

#### Для чого використовується IIFE?

* **Запобігання засміченню глобального простору імен:** до появи ES-модулів (`import`/`export`) IIFE був головним способом ізоляції локальних змінних.
* **Патерн «Модуль» (Module Pattern):** надання публічного інтерфейсу (API) зі збереженням приватних змінних усередині.
* **Фіксація значення змінних циклу:** вирішення відомої проблеми з `var` всередині циклів з асинхронним кодом до появи блокового `let`.

## 2. Налагодження коду (Debugging)

Налагодження — це систематичний процес пошуку, локалізації та усунення помилок і дефектів у програмному забезпеченні.

### 2.1 Техніки налагодження в JS

1. **Методи консолі (Console API):**
   * `console.log()`: стандартний вивід значень для інспекції.
   * `console.table()`: відображає масиви об'єктів або табличні дані у вигляді зручної матриці.
   * `console.dir()`: показує інтерактивний список усіх властивостей JavaScript-об'єкта (зручно для DOM-елементів).
   * `console.warn()` та `console.error()`: виділяють попередження та помилки відповідними кольорами та додають трасування стеку.
   * `console.time()` / `console.timeEnd()`: вимірюють точний час виконання операцій між двома викликами.
   * `console.trace()`: виводить повний стек викликів (Call Stack) до поточної точки коду.

2. **Інструкція `debugger`:**
   * Вбудована команда, яка зупиняє виконання програми та передає керування відладчику браузера, якщо відкрита вкладка DevTools:

     ```javascript
     function calculateTotal(price, tax) {
       debugger; // Виконання зупиняється тут
       return price + (price * tax);
     }
     ```

3. **Можливості інструментів розробника (Browser DevTools):**
   * **Точки зупинки (Line-of-code Breakpoints):** встановлюються кліком на номер рядка у вкладці *Sources* / *Debugger*.
   * **Умовні точки зупинки (Conditional Breakpoints):** виконання зупиняється лише тоді, коли заданий вираз повертає `true`.
   * **DOM Mutation Breakpoints:** зупинка при зміні атрибутів, додаванні або видаленні вузлів дерева DOM.
   * **XHR/Fetch Breakpoints:** зупинка на момент надсилання запиту за заданим URL.
   * **Аналіз стека викликів (Call Stack) та областей видимості (Scope):** перевірка локальних, замикаючих (closure) та глобальних змінних на будь-якому кроці.
   * **Керування кроками виконання:**
     * *Step over* (`F10`): перейти на наступний рядок без заглиблення у виклики функцій.
     * *Step into* (`F11`): увійти всередину функції на поточному рядку.
     * *Step out* (`Shift + F11`): виконати залишок поточної функції та зупинитися одразу після повернення з неї.

## 3. Вбудовані типи помилок (Error Types)

Усі стандартні помилки в JavaScript успадковуються від базового конструктора `Error`.

| Тип помилки | Коли виникає | Приклад |
| :--- | :--- | :--- |
| **`SyntaxError`** | Порушення синтаксису мови під час парсингу коду. | `const x = ;` |
| **`ReferenceError`** | Звернення до неоголошеної змінної або змінної всередині TDZ. | `console.log(undeclaredVar);` |
| **`TypeError`** | Операція над несумісним типом або виклик чогось, що не є функцією. | `const x = null; x.foo();` |
| **`RangeError`** | Числове значення виходить за межі допустимого діапазону. | `new Array(-1);` або переповнення стеку викликів. |
| **`URIError`** | Некоректні параметри передані у функції роботи з URI (`decodeURI` тощо). | `decodeURIComponent('%')` |
| **`EvalError`** | Помилки, пов'язані з глобальною функцією `eval()` (у сучасному JS майже не трапляється). | Специфічні старі варіанти виклику `eval()`. |
| **`AggregateError`** | Об'єднує кілька різних помилок в одну (наприклад, у `Promise.any()`). | Усі проміси були відхилені. |

## 4. Обробка помилок та винятків

### 4.1 Об'єкт `Error`

Базовий об'єкт помилки містить такі ключові властивості:
* **`name`**: назва типу помилки (наприклад, `'Error'`, `'TypeError'`).
* **`message`**: текст повідомлення з описом помилки.
* **`stack`**: стек викликів (рядки файлів та функції, через які пройшла програма до виникнення помилки).
* **`cause`** *(ES2022+)*: посилання на першопричину виникнення помилки (дозволяє створювати ланцюжки помилок).

```javascript
const err = new Error("Не вдалося завантажити профіль", { 
  cause: "Таймаут мережевого з'єднання (5000мс)" 
});

console.log(err.name);    // "Error"
console.log(err.message); // "Не вдалося завантажити профіль"
console.log(err.cause);   // "Таймаут мережевого з'єднання (5000мс)"
```

#### Власні класи помилок (Custom Errors)

Створюються шляхом успадкування від базового класу `Error`:

```javascript
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

// Використання:
// throw new ValidationError("Поле 'email' є обов'язковим", "email");
```

---

### 4.2 Блок `try .. catch`

Дозволяє перехоплювати помилки під час виконання, запобігаючи аварійній зупинці програми.

```javascript
try {
  const parsed = JSON.parse("{ некоректний json }");
} catch (error) {
  console.error("Помилка парсингу:", error.message);
}
```

> **Важливе правило:** Блок `try .. catch` працює **синхронно**. Він не перехоплює винятки всередині асинхронних колбеків, якщо не використовується синтаксис `async/await`:
>
> ```javascript
> // НЕ спрацює:
> try {
>   setTimeout(() => { throw new Error("Помилка"); }, 100);
> } catch (e) { /* Сюди виконання не зайде */ }
>
> // СПРАЦЮЄ:
> async function handleData() {
>   try {
>     await fetch("https://invalid.domain");
>   } catch (err) {
>     console.error("Мережевий запит зазнав невдачі:", err);
>   }
> }
> ```

---

### 4.3 Оператор `throw`

Зупиняє нормальний потік виконання програми та передає об'єкт винятку до найближчого блоку `catch`.

```javascript
function divide(a, b) {
  if (typeof a !== "number" || typeof b !== "number") {
    throw new TypeError("Обидва аргументи мають бути числами");
  }
  if (b === 0) {
    throw new RangeError("Ділення на нуль не допускається");
  }
  return a / b;
}
```

#### Повторне викидання помилок (Re-throwing)

Якщо блок `catch` не знає, як обробити конкретний тип винятку, його слід повторно викинути далі:

```javascript
try {
  processUserData(input);
} catch (error) {
  if (error instanceof ValidationError) {
    displayUserPrompt(error.message);
  } else {
    // Невідома або системна помилка: передаємо на вищий рівень
    throw error;
  }
}
```

---

### 4.4 Блок `try .. catch .. finally`

Код у блоці `finally` виконується **завжди**, незалежно від того, сталася помилка чи код відпрацював успішно.

```javascript
let isProcessing = true;

try {
  performCriticalAction();
} catch (error) {
  console.error("Помилка виконання операції:", error);
} finally {
  // Виконується завжди — ідеальне місце для звільнення ресурсів
  isProcessing = false;
  console.log("Очищення завершено. Прапорець скинуто.");
}
```

> **Примітка щодо виконання:** Навіть якщо блоки `try` чи `catch` містять явний `return`, секція `finally` однаково виконається перед поверненням значення з функції.

## 5. Керування пам'яттю (Memory Management)

У JavaScript керування пам'яттю здійснюється автоматично за допомогою **збирача сміття (Garbage Collector, GC)**.

### 5.1 Життєвий цикл пам'яті

1. **Виділення пам'яті (Allocation):** резервування системної пам'яті під час оголошення змінних, об'єктів та масивів.
2. **Використання (Usage):** зчитування та запис значень у виділену пам'ять.
3. **Звільнення (Release):** очищення пам'яті, яка більше не потрібна програмі.

---

### 5.2 Стек (Stack) проти Купи (Heap)

* **Стек (Stack):** Зберігає примітивні типи даних (`number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) та посилання на об'єкти. Характеризується високою швидкістю доступу, фіксованим розміром елементів та структурою LIFO (Last In, First Out).
* **Купа (Heap):** Зберігає типи за посиланням (`Object`, `Array`, `Function`). Це динамічна неструктурована область пам'яті довільного розміру.

---

### 5.3 Алгоритми збирання сміття

* **Підрахунок посилань (Reference Counting — застарілий):**
  * Відстежує кількість прямих посилань на кожен об'єкт. Коли лічильник досягає `0`, пам'ять звільняється.
  * *Головний недолік:* не здатен виявляти та очищати **циклічні посилання** (коли об'єкт А посилається на об'єкт Б, а Б — на А).

* **Познач і підмітай (Mark-and-Sweep — сучасний підхід, наприклад у движку V8):**
  * Починає роботу від «коренів» (Roots) — глобального об'єкта (`window` / `globalThis`), локальних змінних та параметрів поточного стека викликів.
  * Рекурсивно обходить та позначає всі об'єкти, до яких можна дістатися через посилання.
  * Усі непозначені (недосяжні) об'єкти вважаються «сміттям» і видаляються з пам'яті.

---

### 5.4 Типові причини витоків пам'яті (Memory Leaks) та способи їх уникнення

1. **Випадкові глобальні змінні:**
   * Змінні, створені без оголошення (`var`, `let`, `const`), прикріплюються до глобального об'єкта та ніколи не видаляються.
   * *Вирішення:* Завжди використовувати суворий режим (`"use strict";`) або модулі ES (`ESM`).

2. **Невидалені слухачі подій (Event Listeners):**
   * Якщо елемент видалено з DOM, але зареєстрований обробник події не знято через `removeEventListener()`, елемент залишається в пам'яті.
   * *Вирішення:* Видаляти обробники при демонтуванні компонентів або використовувати `AbortController` із параметром `{ signal: controller.signal }`.

3. **Забуті таймери та інтервали:**
   * Функції, передані в `setInterval()` або `setTimeout()`, утримують змінні своїх замикань доти, доки таймер активний.
   * *Вирішення:* Завжди зупиняти невикористовувані інтервали за допомогою `clearInterval()` або `clearTimeout()`.

4. **Непередбачені замикання:**
   * Утримання посилань на великі об'єкти чи контексти у довгоживучих функціях або глобальних функціях зворотного виклику.

5. **Відокремлені DOM-вузли (Detached DOM Nodes):**
   * Видалення вузла з DOM-дерева в той час, як посилання на нього продовжує зберігатися в масиві чи змінній у JS.
   * *Вирішення:* Онуляти посилання (`element = null`) після вилучення вузла з DOM.

6. **Сильні колекції `Map` та `Set`:**
   * Збереження посилань на об'єкти як ключів у звичайних `Map`/`Set` блокує роботу GC щодо цих об'єктів.
   * *Вирішення:* Використовувати `WeakMap` або `WeakSet`, які не перешкоджають збиранню сміття, якщо інших посилань на об'єкт немає.
