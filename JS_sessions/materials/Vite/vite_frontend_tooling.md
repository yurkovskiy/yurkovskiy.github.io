# Vite: Архітектура, ключові можливості та сучасний інструментарій збірки

**Vite** (французькою «швидкий», вимовляється як */vit/* — «віт») — це сучасний інструмент збірки та локальний сервер розробки для фронтенду, створений Еваном Ю (автором Vue.js). Він кардинально змінив досвід веб-розробки (Developer Experience, DX), розв'язавши хронічні проблеми повільного старту проектів і повільного оновлення модулів (HMR), притаманні традиційним бандлерам (Webpack, Parcel, Rollup).

---

## 1. Чому виник Vite: Проблема традиційних збирачів

### 1.1 Підхід класичних бандлерів (Webpack / Rollup)

До появи нативної підтримки ES-модулів (ESM) у браузерах інструменти збірки були змушені:
1. Просканувати абсолютно **весь вихідний код** проекту та всі залежності з `node_modules`.
2. Побудувати повний граф залежностей у пам'яті.
3. Зібрати весь код в один або кілька бандлів у форматі CommonJS/IIFE.
4. І лише **після повного завершення збірки** запустити локальний dev-сервер.

```
Традиційний бандлер (Webpack):
[Точка входу] ➔ [Аналіз графа всього додатку] ➔ [Бандлінг усього JS] ➔ [Dev Server готовий]
(У великих проектах старт займає від 30 секунд до кількох хвилин!)
```

Коли проект розростався до сотень компонентів і десятків бібліотек, збереження одного файлу викликало помітну затримку оновлення сторінки (2–5 секунд), що знижувало продуктивність розробника.

### 1.2 Революція Vite: Native ES Modules (ESM)

Сучасні браузери (Chrome, Firefox, Safari, Edge) нативно розуміють синтаксис `import` та `export`. Vite використав це фундаментальне зрушення:

* Під час розробки (**Dev mode**) Vite **НЕ збирає весь додаток у бандл**.
* Браузер самостійно запитує потрібний модуль за HTTP, коли зустрічає команду `import`.
* Сервер Vite віддає лише той конкретний файл, який потрібен прямо зараз, транспілюючи його на льоту.

```
Vite Dev Server:
[Старт сервера (мілісекунди!)]
        ▲
        │ Браузер запитує конкретний файл (/src/main.ts)
        ▼
[Vite компілює ЛИШЕ цей файл і віддає його через нативний ESM]
```

## 2. Дводвигунна архітектура Vite (Two-Engine Architecture)

Vite розділяє весь код проекту на дві фундаментальні категорії: **залежності (dependencies)** та **код додатку (source code)**, використовуючи для кожної оптимальний інструмент.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Архітектура Vite                                │
├───────────────────────────────────┬────────────────────────────────────┤
│    Залежності (node_modules)      │       Вихідний код проекту         │
│     (Зрідка змінюються, великі)   │    (Постійно редагується, JSX/TS)  │
├───────────────────────────────────┼────────────────────────────────────┤
│           esbuild                 │            Rollup                  │
│  - Написаний на Go                │  - Гнучка екосистема плагінів      │
│  - У 10–100 разів швидший за JS   │  - Tree-shaking та Code-splitting  │
│  - Pre-bundling у формат ESM      │  - Продакшн-оптимізація (Build)    │
└───────────────────────────────────┴────────────────────────────────────┘
```

### 2.1 esbuild (Pre-bundling залежностей)
* `esbuild` написаний на мові **Go** і компілюється в нативний машинний код. Він обробляє залежності у десятки разів швидше за інструменти на JavaScript.
* **Попереднє бандлування (Dependency Pre-bundling):** Багато NPM-бібліотек досі публікуються у застарілому форматі CommonJS або UMD (наприклад, `react`). Під час першого запуску Vite конвертує такі пакети в нативний ESM за допомогою `esbuild` і кешує їх у папці `node_modules/.vite`.
* Об'єднує пакети з сотнями внутрішніх файлів (наприклад, `lodash-es`) в один модуль, щоб браузер не надсилав 600 паралельних HTTP-запитів.

### 2.2 Rollup (Продакшн збірка)
* Для команди `vite build` використовується стабільний та перевірений часом **Rollup**.
* Він забезпечує максимальну якість фінального бандла: видалення мертвого коду (**Tree-shaking**), розділення на чанки (**Code Splitting**), оптимізацію завантаження CSS і генерацію прелоад-директив (`<link rel="modulepreload">`).

## 3. Ключові можливості та фічі Vite

### 3.1 Блискавичний Hot Module Replacement (HMR)
У Vite швидкість оновлення модуля при збереженні файлу **не залежить від загального розміру проекту**. Оскільки оновлюється лише один модуль, передача коду через WebSocket і оновлення в DOM відбуваються практично миттєво (зазвичай менше ніж за 50 мс), зі збереженням поточного стану додатку в браузері.

### 3.2 Першокласна підтримка TypeScript "з коробки"
* Vite підтримує імпорт файлів `.ts` та `.tsx` одразу без встановлення додаткових лоадерів.
* **Важливий нюанс:** Vite використовує `esbuild` для **транспіляції** (видалення типів), але **НЕ виконує перевірку типів (Type Checking)** під час dev-сервера. Це робиться навмисно заради максимальної швидкості.
* Для перевірки типів перед релізом запускається оригінальний компілятор: `tsc --noEmit`.

### 3.3 Обробка CSS та препроцесорів
* **CSS Modules:** Будь-який файл із суфіксом `.module.css` автоматично стає модульним (генеруються унікальні хешовані класи).
* **Препроцесори:** Підтримка SCSS/SASS або Less вмикається простим встановленням пакета (`npm i -D sass`) — жодних налаштувань у конфігурації не потрібно.
* **PostCSS:** Автоматично застосовує конфігурацію з файлу `postcss.config.js`.

### 3.4 Робота зі статичними ресурсами (Static Assets)
* Імпорт зображення чи шрифту повертає публічний URL:
  ```typescript
  import logoUrl from './assets/logo.svg';
  // logoUrl містить шлях або base64 data-uri
  ```
* Імпорт файлу як рядка (Raw import):
  ```typescript
  import shaderCode from './shader.glsl?raw';
  ```
* Запуск Web Worker в один рядок:
  ```typescript
  import MyWorker from './worker.ts?worker';
  const worker = new MyWorker();
  ```

## 4. Порівняння: Vite проти Webpack

| Критерій | Webpack | Vite |
| :--- | :--- | :--- |
| **Швидкість старту dev-сервера** | Повільна (секунди або хвилини через повний бандлінг) | Миттєва (100–300 мс, сервер стартує без бандлінгу) |
| **Швидкість HMR** | Уповільнюється з ростом кодової бази | Константна, не залежить від розміру проекту |
| **Транспіляція в Dev** | Babel / ts-loader (JavaScript) | `esbuild` (компільований Go) |
| **Формат модулів у Dev** | Власна емуляція модулів Webpack | Нативні ES-модулі браузера (ESM) |
| **Конфігурація** | Складна, багатослівна (`module.rules`, `plugins`) | Мінімальна, більшість фіч працює з коробки |
| **Збірка на Production** | Webpack Compiler | Rollup (висока якість оптимізації) |

## 5. Практичний старт та налаштування проекту

### 5.1 Створення нового проекту через CLI

Офіційний генератор дозволяє обрати будь-який шаблон (Vanilla TS, React, Vue, Svelte):

```bash
# Інтерактивне створення
npm create vite@latest my-app

# Швидке створення проекту на чистому TypeScript
npm create vite@latest my-ts-app -- --template vanilla-ts
cd my-ts-app
npm install
npm run dev
```

### 5.2 Анатомія файлу `vite.config.ts`

Хоча Vite працює з нульовою конфігурацією, для серйозних проектів створюється файл `vite.config.ts`:

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import path from 'node:path';

export default defineConfig({
  // Базовий публічний шлях (корисно для GitHub Pages: '/my-repo/')
  base: './',

  // Налаштування сервера розробки
  server: {
    port: 3000,
    open: true, // Автоматично відкривати браузер при старті
    cors: true,
    // Вбудований Reverse Proxy (вирішує проблему CORS на етапі dev!)
    proxy: {
      '/api': {
        target: 'https://bank.gov.ua',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  },

  // Псевдоніми шляхів (Path Aliases)
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
      '@models': path.resolve(__dirname, './src/models'),
      '@services': path.resolve(__dirname, './src/services')
    }
  },

  // Налаштування фінальної збірки
  build: {
    outDir: 'dist',
    sourcemap: true,
    // Налаштування параметрів Rollup
    rollupOptions: {
      output: {
        manualChunks: {
          // Винесення великих бібліотек в окремий вендор-чанк
          vendor: ['bootstrap']
        }
      }
    }
  }
});
```

### 5.3 Робота зі змінними оточення (`.env`)

Vite підтримує змінні середовища за замовчуванням:
* Лише змінні з префіксом **`VITE_`** потрапляють у клієнтський код (захист від витоку приватних ключів API).
* Доступ до них здійснюється через сучасний об'єкт **`import.meta.env`** замість `process.env`:

```env
# .env
VITE_API_BASE_URL=https://api.myproject.ua/v1
DB_PASSWORD=secret_server_pass # НЕ потрапить у браузер!
```

```typescript
// src/app.ts
const apiUrl = import.meta.env.VITE_API_BASE_URL;
console.log('Підключення до API:', apiUrl);

// Вбудовані булеві прапорці:
if (import.meta.env.DEV) {
  console.log('Режим розробки');
}
```

## 6. Резюме та висновки

* **Vite — це не просто бандлер, а повноцінне середовище розробки.**
* У режимі розробки він покладається на нативні ES-модулі браузера та надшвидкий `esbuild`.
* У режимі продакшну використовує перевірений `Rollup`, гарантуючи якісний code-splitting та tree-shaking.
* Vite є стандартом де-факто для сучасної екосистеми Vue, React (без Next.js), Svelte, Solid, а також для проектів на чистому TypeScript.
