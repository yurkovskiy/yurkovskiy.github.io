# Що таке `package.json` і як з ним працювати?

**`package.json`** — це головний конфігураційний файл будь-якого Node.js або сучасного фронтенд-проєкту. Він містить метадані про проєкт (назву, версію, автора), список необхідних бібліотек (залежностей) та команди (скрипти) для автоматизації роботи.

---

## 1. Як створити `package.json`?

Щоб створити цей файл у кореневій папці вашого проєкту, відкрийте термінал і виконайте одну з команд:

* **Інтерактивний режим** (термінал ставитиме запитання про назву, версію, опис тощо):
  ```bash
  npm init
  ```
* **Швидкий режим** (створить файл автоматично зі стандартними налаштуваннями):
  ```bash
  npm init -y
  ```

---

## 2. Приклад структури `package.json`

Ось як виглядає типовий файл реального проєкту:

```json
{
  "name": "my-awesome-app",
  "version": "1.0.0",
  "description": "Мій перший вебзастосунок на Node.js",
  "main": "index.js",
  "type": "module",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest",
    "build": "vite build"
  },
  "keywords": ["nodejs", "web", "app"],
  "author": "Іван Франко <ivan@example.com>",
  "license": "MIT",
  "dependencies": {
    "express": "^4.18.2",
    "axios": "~1.6.0"
  },
  "devDependencies": {
    "jest": "^29.7.0",
    "nodemon": "^3.0.1"
  },
  "engines": {
    "node": ">=18.0.0"
  }
}
```

---

## 3. Детальний розбір основних полів

### Метадані проєкту
* **`name`** *(обов'язкове)* — назва проєкту. Повинна складатися лише з малих літер, без пробілів (можна використовувати дефіс `-` або підкреслення `_`).
* **`version`** *(обов'язкове)* — поточна версія проєкту у форматі `MAJOR.MINOR.PATCH` (наприклад, `1.0.0`).
* **`description`** — короткий опис того, що робить ваш проєкт (допомагає при пошуку в реєстрі npm).
* **`main`** — головний файл (точка входу) вашого застосунку (зазвичай `index.js` або `app.js`).
* **`type`** — визначає систему модулів у Node.js:
  * `"commonjs"` (за замовчуванням) — використання `require()` та `module.exports`.
  * `"module"` — використання сучасних ES-модулів (`import` та `export`).
* **`license`** — тип ліцензії, під якою розповсюджується код (найпопулярніша відкрита ліцензія — `"MIT"`).
* **`private`** — якщо встановити `true`, npm заблокує випадкову публікацію цього проєкту у відкритий реєстр npm.

### Скрипти (`scripts`)
Це об'єкт із псевдонімами для консольних команд, які спрощують розробку, збірку та тестування.

* Стандартні команди (`start`, `test`) можна запускати без слова `run`:
  ```bash
  npm start
  npm test
  ```
* Власні (кастомні) команди запускаються через `npm run <назва_скрипта>`:
  ```bash
  npm run dev
  npm run build
  ```

## 4. Залежності: `dependencies` проти `devDependencies`

Усі сторонні пакети, які ви встановлюєте, поділяються на дві категорії:

### 1. `dependencies` (Бойові залежності)
Бібліотеки, без яких застосунок **не зможе працювати** у продакшені (на реальному сервері або в браузері користувача).
* *Приклади:* `react`, `express`, `axios`, `lodash`.
* *Як встановити:*
  ```bash
  npm install express
  ```

### 2. `devDependencies` (Залежності для розробки)
Інструменти, які потрібні **лише розробнику** під час написання, форматування, збірки чи тестування коду. На продакшн-сервер вони не потрапляють.
* *Приклади:* `jest`, `eslint`, `prettier`, `nodemon`, `vite`, `typescript`.
* *Як встановити (з прапорцем `-D` або `--save-dev`):*
  ```bash
  npm install -D jest
  ```

## 5. Семантичне версіонування (SemVer) та символи `^` і `~`

Версії пакетів складаються з трьох цифр: **`MAJOR.MINOR.PATCH`** (наприклад, `4.18.2`):
1. **MAJOR (4)** — мажорне оновлення (глобальні зміни, які можуть зламати зворотну сумісність зі старим кодом).
2. **MINOR (18)** — мінорне оновлення (додано новий функціонал без порушення старого).
3. **PATCH (2)** — патч (виправлення багів та помилок безпеки).

Перед номером версії у `package.json` часто стоять спеціальні символи, які вказують npm, які оновлення дозволено завантажувати:

| Символ | Приклад | Що означає | Які версії встановить |
| :--- | :--- | :--- | :--- |
| **`^`** (каретка) | `^4.18.2` | Дозволяє оновлювати **MINOR** та **PATCH**, але фіксує MAJOR. | Від `4.18.2` до `< 5.0.0` (напр. `4.19.1`) |
| **`~`** (тильда) | `~4.18.2` | Дозволяє оновлювати лише **PATCH**, фіксуючи MAJOR та MINOR. | Від `4.18.2` до `< 4.19.0` (напр. `4.18.9`) |
| *Без символу* | `4.18.2` | Жорстка фіксація. Встановиться виключно вказана версія. | Тільки `4.18.2` |
| **`*`** (зірочка) | `*` | Завжди завантажувати найновішу версію (небезпечно для проєктів). | Будь-яка остання версія |

---

## 6. Що таке `package-lock.json`?

Коли ви встановлюєте будь-який пакет, поруч із `package.json` автоматично створюється файл **`package-lock.json`**.

* **Для чого він потрібен?** У `package.json` вказані приблизні діапазони версій (через `^` або `~`). `package-lock.json` фіксує **точні версії** кожного встановленого пакета та всіх його підзалежностей.
* **Головне правило:** Файл `package-lock.json` **обов'язково потрібно додавати в Git** (не додавати у `.gitignore`). Це гарантує, що у всіх розробників команди та на сервері встановиться ідентичний набір бібліотек без конфліктів версій.
