## 1. Вступ: яку проблему вирішує Bootstrap? (5 хв)

Почніть із запитання: *«Скільки часу вам знадобиться, щоб створити сторінку, яка добре виглядає і на телефоні, і на планшеті, і на комп'ютері — з робочим меню навігації — з нуля?»*

Покажіть дві речі поруч:
- Сира, неоформлена HTML-сторінка (виглядає погано, не адаптивна).
- Той самий контент, оформлений за допомогою Bootstrap (виглядає охайно, адаптивний) — змінюйте розмір вікна браузера наживо, щоб показати, як він підлаштовується.

**Ключова фраза:** *«Bootstrap не пише сайт за вас — він дає спільну "мову" та готові будівельні блоки, як LEGO, щоб не винаходити велосипед щоразу заново.»*

## 2. Філософія Bootstrap (10 хв)

Представте це як чотири стовпи. Записуйте їх на дошці/слайді по мірі пояснення.

### а) Mobile-First (спочатку мобільні)
CSS у Bootstrap написаний, *починаючи* з найменшого екрана, а потім додаються правила для більших екранів через медіа-запити `min-width`. Це змушує розробників спочатку думати про найважливіший контент, а потім поступово покращувати — замість того, щоб втискати десктопну верстку в телефон "заднім числом".

### б) Адаптивність за замовчуванням
Усе (сітка, зображення, навбари, типографіка) побудовано так, щоб автоматично перебудовуватися залежно від точок перелому (breakpoints): `sm`, `md`, `lg`, `xl`, `xxl`. Ви описуєте *намір* («ця колонка займає 4/12 на середніх екранах і більше»), а не позиціонуєте елементи піксель у піксель.

### в) На основі компонентів / «Не винаходь велосипед»
Поширені UI-шаблони (кнопки, картки, модальні вікна, алерти, навбари) вже готові, протестовані на доступність та кросбраузерність. Ви збираєте сторінки з цих блоків, замість того щоб писати CSS з нуля.

### г) Зручність через утиліти (utility-first)
Крім компонентів, Bootstrap містить невеликі класи-утиліти з однією функцією (`d-flex`, `mt-3`, `text-center`, `p-2`), щоб ви могли робити невеликі стильові правки прямо в HTML, не пишучи власний CSS.

**Питання для обговорення (1 хв):** *«У чому компроміс використання такого фреймворку?»* → Підведіть до відповіді: швидша розробка та узгодженість, але менш унікальний візуальний стиль і трохи зайвої "ваги" файлів, якщо частина стилів не використовується.

## 3. Налаштування (5 хв)

Покажіть мінімальний базовий шаблон — без інструментів збірки, лише посилання на CDN.

```html
<!DOCTYPE html>
<html lang="uk">
<head>
  <meta charset="UTF-8">
  <!-- Цей meta-тег і Є філософією mobile-first в одному рядку -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Демо Bootstrap</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body>

  <h1 class="text-center mt-4">Привіт, Bootstrap!</h1>

  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
</body>
</html>
```

**Обов'язково наголосіть на:** тезі `<meta name="viewport">`. Без неї жодна адаптивна поведінка не працює — це "місток" між філософією та кодом.

## 4. Система сітки (Grid) та адаптивний дизайн (15 хв)

Спочатку поясніть модель мислення: **12 колонок у рядку.** Ви самі вирішуєте, скільки з цих 12 колонок займає кожен елемент, і це число може змінюватися залежно від точки перелому.

```html
<div class="container">
  <div class="row">
    <div class="col-12 col-md-4 bg-primary text-white p-3">Колонка 1</div>
    <div class="col-12 col-md-4 bg-secondary text-white p-3">Колонка 2</div>
    <div class="col-12 col-md-4 bg-success text-white p-3">Колонка 3</div>
  </div>
</div>
```

Розберіть уголос:
- `col-12` → «на дуже маленьких екранах — займай всю ширину (стек по вертикалі)».
- `col-md-4` → «на середніх екранах і більших — займай 4 з 12 колонок (три поруч)».

**Демонстрація наживо:** повільно змінюйте розмір вікна браузера і дивіться, як колонки складаються в стек і розкладаються назад. Це найпотужніший момент "ага!" усього заняття — приділіть йому справжню увагу.

**Шпаргалка по точках перелому (покажіть як таблицю):**

| Точка перелому | Префікс | Мінімальна ширина |
|---|---|---|
| Дуже маленька | *(немає)* | <576px |
| Маленька | `sm` | ≥576px |
| Середня | `md` | ≥768px |
| Велика | `lg` | ≥992px |
| Дуже велика | `xl` | ≥1200px |

## 5. Mobile-First — демонстрація наживо (10 хв)

Закріпіть філософію на щойно створеній сітці:

- Почніть з інструментів розробника в мобільному режимі перегляду (або з вузького вікна браузера). Зверніть увагу: *«Класи за замовчуванням (`col-12`) — це те, що застосовується тут: базовий, найменший варіант»*.
- Розширте вікно / перемкніться на десктопний режим. Зверніть увагу: *«Тепер вступає в дію `col-md-4` і перевизначає розкладку, бо ми перетнули точку перелому `md`»*.

**Ключова фраза:** *«Ви не пишете 'якщо десктоп — роби X'. Ви пишете правила, які застосовуються від певної точки перелому і вище. Це і є mobile-first: маленький екран — це база за замовчуванням, а більші екрани — це виняток, який ви підключаєте додатково.»*

Додатково (за наявності часу): покажіть, як виглядав би підхід "desktop-first" — базові стилі для десктопа, а потім медіа-запити `max-width` для перевизначення під мобільні — просто щоб зробити різницю наочною.

## 6. Навбар + гамбургер-меню (10 хв)

Тут усе поєднується в один реальний приклад: компоненти + адаптивність + mobile-first одночасно.

```html
<nav class="navbar navbar-expand-lg navbar-dark bg-dark">
  <div class="container-fluid">
    <a class="navbar-brand" href="#">MySite</a>

    <!-- Кнопка-гамбургер: видима лише нижче точки перелому "lg" -->
    <button class="navbar-toggler" type="button"
            data-bs-toggle="collapse" data-bs-target="#navMenu">
      <span class="navbar-toggler-icon"></span>
    </button>

    <div class="collapse navbar-collapse" id="navMenu">
      <ul class="navbar-nav ms-auto">
        <li class="nav-item"><a class="nav-link" href="#">Головна</a></li>
        <li class="nav-item"><a class="nav-link" href="#">Про нас</a></li>
        <li class="nav-item"><a class="nav-link" href="#">Контакти</a></li>
      </ul>
    </div>
  </div>
</nav>
```

Поясніть кожну частину:
- `navbar-expand-lg` → *«Показуй повне меню на великих екранах і більших; нижче цього — згортай його»*. Це знову mobile-first у дії — згорнутий стан/гамбургер є станом за замовчуванням для маленьких екранів.
- `navbar-toggler` + `data-bs-toggle="collapse"` → JavaScript від Bootstrap сам обробляє відкриття/закриття, без написання власного коду.
- `ms-auto` → клас-утиліта, який притискає посилання меню праворуч.

**Демонстрація наживо:** змінюйте розмір вікна і дивіться, як повне меню згортається в іконку гамбургера, потім клацніть по ній, щоб показати відкриття/закриття.

# Додаток: Словник використаних CSS-класів

Довідник по кожному класу Bootstrap, використаному в занятті, згрупований за розділами. Роздайте його разом із планом або тримайте відкритим під час живого кодування.

## Компонування / Сітка (Layout / Grid)

| Клас | Що робить |
|---|---|
| `container` | Центрує вміст і додає адаптивні відступи по боках; ширина змінюється на кожній точці перелому. |
| `container-fluid` | Як і `container`, але завжди 100% ширини на будь-якій точці перелому. |
| `row` | Горизонтальна обгортка для колонок; додає від'ємний відступ, щоб компенсувати внутрішні відступи колонок. |
| `col-12` | Колонка займає всі 12 з 12 одиниць сітки (повна ширина) — застосовується від найменшого екрана і вище. |
| `col-md-4` | Колонка займає 4 з 12 одиниць сітки, починаючи з точки перелому `md` (≥768px) і вище. |

## Утиліти відступів (Spacing)

Класи відступів у Bootstrap мають шаблон `{властивість}{сторони}-{розмір}`.
- Властивість: `m` (margin/зовнішній відступ) або `p` (padding/внутрішній відступ)
- Сторони: `t` (top/верх), `b` (bottom/низ), `s` (start/ліва сторона), `e` (end/права сторона), `x` (ліво+право), `y` (верх+низ), або без літери (усі сторони)
- Розмір: `0`–`5` (за зростаючою шкалою) або `auto`

| Клас | Що робить |
|---|---|
| `p-3` | Внутрішній відступ з усіх боків, розмір 3 (1rem / 16px). |
| `mt-4` | Зовнішній відступ зверху, розмір 4 (1.5rem / 24px). |

## Утиліти кольору / фону

| Клас | Що робить |
|---|---|
| `bg-primary` | Встановлює колір фону як основний колір теми (за замовчуванням — синій). |
| `bg-secondary` | Встановлює колір фону як вторинний колір теми (за замовчуванням — сірий). |
| `bg-success` | Встановлює колір фону як колір "успіху" (за замовчуванням — зелений). |
| `bg-dark` | Встановлює темний/майже чорний колір фону. |
| `text-white` | Встановлює білий колір тексту — часто поєднується з темним фоном для контрасту. |

## Утиліти тексту

| Клас | Що робить |
|---|---|
| `text-center` | Центрує текст по горизонталі. |

## Кнопки

| Клас | Що робить |
|---|---|
| `btn` | Базовий клас кнопки — обов'язковий для будь-якої кнопки Bootstrap; додає відступи, заокруглення кутів, стиль курсора. |
| `btn-primary` | Додає стилізацію основним кольором теми поверх `.btn`. |

## Картки (Cards)

| Клас | Що робить |
|---|---|
| `card` | Контейнер з рамкою, заокругленими кутами та відступами — базова обгортка для компонента картки. |
| `card-body` | Додає внутрішні відступи навколо вмісту картки. |
| `card-title` | Стилізує елемент (зазвичай заголовок) як назву картки (налаштовує відступи/жирність шрифту). |
| `card-text` | Прибирає стандартний нижній відступ у параграфів усередині картки для узгодженого вигляду. |

## Алерти (сповіщення)

| Клас | Що робить |
|---|---|
| `alert` | Базовий клас сповіщення — додає відступи, рамку та заокруглені кути. |
| `alert-warning` | Додає жовту колірну схему "попередження" поверх `.alert`. |

## Навбар (панель навігації)

| Клас | Що робить |
|---|---|
| `navbar` | Базовий клас компонента панелі навігації. |
| `navbar-expand-lg` | Навбар показується в повному/розгорнутому вигляді, починаючи з точки перелому `lg` (≥992px); нижче цього — згортається в гамбургер-меню. |
| `navbar-dark` | Налаштовує колір тексту/іконок навбара для використання на темному фоні. |
| `navbar-brand` | Стилізує посилання з логотипом/назвою сайту в навбарі (більший текст, спеціальні відступи). |
| `navbar-toggler` | Стилізує саму кнопку-гамбургер (рамка, відступи, стан фокусу). |
| `navbar-toggler-icon` | Графічна іконка гамбургера всередині кнопки-перемикача. |
| `navbar-nav` | Стилізує `<ul>` як список посилань навігації навбара (прибирає маркери списку, налаштовує flex-розкладку). |
| `nav-item` | Обгортає кожен `<li>` у списку навбара; переважно семантичний елемент/точка для стилізації. |
| `nav-link` | Стилізує `<a>` як посилання навігації (відступи, колір, стан наведення). |
| `collapse` | Позначає елемент як такий, що згортається — прихований за замовчуванням, показується при перемиканні. |
| `navbar-collapse` | Поєднується з `collapse`; спеціально відповідає за поведінку згортання вмісту навбара на маленьких екранах. |
| `ms-auto` | Margin-start: auto — притискає елемент (і все, що після нього) праворуч у flex-контейнері. |

## Атрибути даних Bootstrap (не CSS-класи, але використовуються разом із ними)

| Атрибут | Що робить |
|---|---|
| `data-bs-toggle="collapse"` | Повідомляє JavaScript Bootstrap, що клацання по цьому елементу має перемикати згортання пов'язаного елемента. |
| `data-bs-target="#navMenu"` | Вказує, *який саме* елемент (за ID) перемикається при клацанні по цій кнопці. |
